# Insights

Use fresh runtime `sol_query` observations for supported recorded facts first. Delegate bounded interpretation through one native `task` only when meaningful deterministic aggregates are available; give explicit read-only scope, sources, sample-size expectations, and no shell or tests unless requested. A single explicit verification can use one native task with the exact check. Reserve `sol_plan` with Planner and `sol_run({planId})` for multi-step analysis, dependencies or material decisions; planned workers use trusted packets, registered checks, and source observations.

Do not invent metrics or infer sensitive traits. Delegate approved reversible tuning through one bounded native task with explicit writes and verification, or within an existing multi-step plan. Ask before changing cost, autonomy or quality gates; after native task follow-up, normally use native `question` directly. Appropriate existing non-Sol skills remain available through relevant assignments.
