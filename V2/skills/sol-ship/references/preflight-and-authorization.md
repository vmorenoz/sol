# Preflight y autorización de Ship · sol-ship refs@1

Procedimiento para la capacidad nativa de Ship. `sol_ship_preflight` prepara y devuelve la vista previa; preflight no autentica al usuario ni autoriza efectos. `sol_ship_authorize` es la única entrada nativa pública para registrar autorización tras consentimiento explícito y aprobación del host. La autorización guardada no es permiso del runtime. No usa `gh pr create --dry-run` como sustituto de preflight no-publicador ni shell arbitrario para superar falta de tool/permisos.

## Secuencia

1. **Preparar localmente:** confirmar Work/revisión/AC y evidencia requerida vigente; obtener status, rama actual, upstream/remoto, base y diff; inspeccionar qué commits/rutas se incluirían. Identificar commits ajenos/locales no relacionados y si forman ancestros que se publicarían. No staging `git add -A`, stash/reset ni cambiar branch del usuario.
2. **Preflight sin efectos remotos:** vía tool nativa, construir snapshot reproducible: root, branch/base, remote/destino, paths, commits/inclusiones, título/body PR y secuencia exacta de acciones. Un preflight no autentica al usuario ni autoriza; no push/PR durante preview. Si tool real no está disponible, detener y reportar.
3. **Explicar antes de preguntar:** presentar contenido/destino/actions, checks, commits ajenos detectados y consecuencias. Excluirlos por defecto; si incluirlos resulta inevitable para push del branch, exponerlo como parte del snapshot y solicitar permiso específico. User «ship it» no aclara un destino/contenido desconocido.
4. **Autorizar snapshot exacto:** pedir consentimiento explícito para este snapshot/destino/acciones; el modo allow/auto del host no sustituye este consentimiento para un alcance nuevo ni autoriza aprobar mediante booleano del modelo o manipulaciones directas. Tras el sí, invocar `sol_ship_authorize` según su contrato nativo vigente. Un permiso efectivo allow/auto puede permitir la invocación sin diálogo; la ausencia de popup no equivale a denegación ni se espera atestación criptográfica de UI. No afirmar autorización registrada hasta confirmación de la tool. Sol invoca `sol_ship_authorize` privilegiado y respeta el resultado y políticas reales del host; si el host niega o el snapshot cambia, la operación se bloquea. No declares verificado el comportamiento interactivo del host sin observarlo en esa sesión. Cada efecto sigue sujeto a host approval/permisos; el registro Sol no los salta.
5. **Invalidar si cambia:** cambio de bytes/paths, commits, destino, base o acciones invalida el preview y autorización anterior. Obtener snapshot/preflight nuevo y autorización nueva. No reusar confirmación histórica.
6. **Ejecutar acciones exactas:** validar cada efecto; jamás merge/tag/release/deploy/force-push, `git add -A`, publicar trabajo ajeno o esconder dirty changes sin autorización aparte. No inferir que permisos del host bloquean otros caminos.
7. **Recibo observado:** reportar commit hash si creado, branch/remote, resultado real del push, URL/ID PR observada, errores/acciones no ejecutadas y evidencia vigente. No declarar deploy, merge o aprobación si no ocurrió.
8. **Conciliar metadata:** registrar receipts reales solo por flujo/API nativo vigente y revisión actual. No falsificar resultados ni editar archivos canónicos directamente.

## Registros canónicos y autoridad

El ledger conserva eventos como `shipping.intent.record`, `shipping.approval.record`, `shipping.intent.invalidate` y `shipping.receipt.record`. Son registros internos: `shipping.approval.record` no autoriza por sí mismo y está filtrada/rechazada en la acción pública `sol_work_apply`; jamás la invoques directamente ni fabriques payload. La autoridad privada de sesión en cache/memoria se diferencia de la metadata declarativa del ledger; la persistencia de eventos no reactiva permisos sin un pase de autorización vigente. Usa exclusivamente `sol_ship_authorize` para autorización pública y sigue los campos que esa tool exponga. El registro no es autenticación ni token, identidad autenticada, permiso runtime o prueba de efecto; es consentimiento reportado ligado al intent/snapshot. No edites metadata por filesystem.
